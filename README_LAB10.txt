These scripts are based on the examples provided on Monday. Modified in order to work without the library that was needed to make those scripts work.

Saving Transforms:
	Transform data is logged within a created TransfromClass. It stores the local position, local rotation, and local scale of an object.
	The ISaveable interface works to define what transform savers need to have. A SaveID which stores their transform class and a SavedData dictionary which stores their ID and a TransformClass to store their transform data in a serializable format.
	TransformSaver then inherits from ISaveable and MonoBehavior and serves as a practical way to save the information. It implements the SaveID and sets the information within the transform class upon saving the game. It implements the SaveData by utilizing an alterable LOCAL_TRANSFORM_KEY and the SaveID to create a new dictionary entry. The LOCAL_TRANSFORM_KEY is set by the targetDirector if on a target or set manually if attached to a player.
	The SavingService has functions for saving transform information, as well as other information if added, in a Json format. Being passed a file name it finds every object with the ISaveable mark in the scene. For each object found their savedata is obtained and the keys within the SaveData are checked. If a valid key is found it is then the SaveData is then added to the savedObjects dictionary, with duplicate entries having a number appended to them in order to prevent errors. The complete dictionary containing all of the saved data is then passed into a SaveWrapper class which works to put all of the content into a format a Json file can understand. Finally the information is saved to a JsonFile using a StreamWriter with unecessary spare data being cleared afterwards.
	The SaveManager works as a way to use the save functionality. By pressing 'S' you can save the game state with both Score and Transforms being saved via the save manager.

Loading Transforms:
	SavingService trys to find the provided file in the persistantDataPath's directory and then checks if the file exists. If the file exists the StreamReader will then read the file and translate it from Json formatting to a SaveWrapper. The data within is then sorted into a new dictionary, since the keys and content were broken into indvidual lists upon being saved, in order to be in a serializable format. After that dictionary is compiled the Dictionary is returned as the value provided by the LoadPositions function.
	The SaveManager then uses that data proved by the SavingService to restore the positions of everything in the scene. Due to the way the prior scripts work, I opted to delete every active target on the screen and then spawn in new targets of the type saved in the ID of the target within the SaveData. If a standard target is loaded then a standard target will be created and moved to the transform position corresponding to where the original target was. If a fast target was saved then the same thing will happen but with a fast target being built instead. The player is the exception to this with the player being already in the scene by default. So the SaveManager simply finds the player and moves them instead. Finally the spawning interval for targets is reset, so that way one target doesn't instantly spawn and ruin the refresh. The SaveManager also handles activating this function. By pressing 'L' on the keyboard the game's save data can be loaded for both the score and transforms.

Saving Scores:
	ScoreSaver finds the score currently saved in the scene from the Singleton ScoreManager and then converts it to binary using a Binary formatter and then saves the information in a .txt file for reading later. Saved to a file instead of to memory because there were issues carrying over the byte arrays between the saving and loading functions. After the information is saved to the file unecessary information is then cleared from the system.
	SaveManager handles calling the SaveScore function when the game is saved.

Loading Scores:
	ScoreSaver finds the file which stores the current score in the persistentDataPath's directory while checking if the file exists just in case. Then it translates the information within the file back to usable information and then returns the loaded score as a float.
	ScoreManager's LoadScore function runs the ScoreSaver's LoadScore function and sets its own score value equal to it. Finally, it updates the UI to match the stored value.
	SavingService handles calling the LoadScore function from the Singleton ScoreManager when the game is loaded.
